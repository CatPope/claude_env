# claude_env 요구사항

- 기준일: 2026-09-29
- 출처: `docs/기획/초안.txt`, `docs/planning/spec-deep-interview.md`(요구사항 인터뷰), `docs/planning/plan-ralplan.md` rev 5(합의 계획과 그 과정의 사용자 결정)
- 이 문서는 위 세 문서의 확정된 요구사항을 한곳에 모은 것이다. 구현 방법은 계획 문서를 본다.

## 1. 개요

Windows Terminal에서 Claude Code를 여러 탭으로 쓰는 사용자를 위한 트레이 상주 도구다.

- 터미널을 닫아도 작업이 날아가지 않게 한다.
- 다시 열면 창·탭·분할과 각 Claude 대화를 자동으로 되살린다.
- 탭 제목으로 어느 프로젝트, 어느 계정, 무슨 작업인지 알 수 있게 한다.
- 2차에서는 여러 구독 계정을 사용량 한도 전에 자동으로 바꿔 쓴다.

평소에는 창을 열지 않고 자동으로 동작한다. UI는 설정할 때만 쓴다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 1차 | 세션 보존·복원, 탭 제목, 트레이 설정 UI |
| 2차 | 계정 무중단 전환 |
| 대상 환경 | Windows 11, Windows Terminal, Claude Code 구독 계정(Pro/Max). 우선 개발자 본인 PC |

## 3. 용어

| 용어 | 뜻 |
|---|---|
| 방식 A | 탭에서 `claude`를 평소처럼 대화형으로 실행한다. **기본값.** |
| 방식 C | Claude Code 백그라운드 세션(`claude --bg`)을 띄우고 탭은 `claude attach`로 붙는다. 창을 닫아도 응답이 끝까지 진행된다. **프로젝트별 선택.** |
| 별칭 | 프로젝트의 표시 이름. 기본값은 폴더 이름. |
| 세션 부제 | 탭 제목 끝에 붙는 세션별 이름. 같은 프로젝트의 탭을 구분한다. |
| 중단됨 | 응답 도중이나 입력 대기 중에 창이 닫힌 세션의 상태. |

## 4. 기능 요구사항

### 4.1 세션 보존·복원 (1차)

| ID | 요구사항 |
|---|---|
| FR-1 | 응답 도중에 창을 닫으면: **A**에서는 그 세션을 "중단됨"으로 기록하고, 다시 열 때 같은 대화로 이어갈 수 있게 한다. **C**에서는 응답을 끝까지 마친다. |
| FR-2 | 창을 닫은 뒤에도 대화 기록이 `claude --resume` 목록에 남는다. **A**에서는 마지막 사용자 메시지와 이미 끝난 답변을 보장한다. 쓰던 중이던 답변의 끝부분은 빠질 수 있다(사용자 승인). **C**에서는 전부 남는다. |
| FR-3 | 복원 기능이 켜져 있으면 Windows Terminal을 열기만 해도 이전의 창 개수, 탭 순서, 분할 배치가 되살아난다. 사용자 조작은 필요 없다. |
| FR-4 | 되살아난 Claude 탭은 원래 폴더에서 원래 대화로 이어진다. Windows에서 실행한 Claude만 대상이다. |
| FR-5 | 되살아난 일반 셸 탭(PowerShell 5.1·7, Git Bash, WSL)은 원래 셸 종류와 폴더로 열린다. WSL 탭은 셸과 폴더만 복원하고 Claude는 자동 실행하지 않는다. |
| FR-6 | 창 여러 개를 차례로 닫아도 모든 창이 복원된다. (Windows Terminal은 기본적으로 마지막 창만 기억한다.) |
| FR-7 | 중단됨 세션은 복원 후 탭 제목에 표시되고, 첫 프롬프트를 보내면 표시가 사라진다. 설정으로 "자동 이어가기"를 켜면 복원 직후 이어가기 프롬프트를 자동으로 보낸다(기본 끔). |
| FR-8 | **C**에서 창을 닫은 뒤 세션은 Claude Code 기본 동작대로 약 1시간 유지된다. 그동안 권한 요청이나 선택지 질문 같은 입력 대기가 생기면 Windows 알림을 보낸다. 알림을 누르면 그 세션이 새 탭에 열린다. 클릭이 안 되는 환경에서는 트레이 메뉴 "입력 대기 세션 N개"에서 연다. |
| FR-9 | **C**에서 Claude가 파일을 고치는 위치는 프로젝트별로 정한다. 기본은 원래 폴더이고, git worktree 사본으로 바꿀 수 있다. 전역 Claude 설정은 바꾸지 않는다. |

### 4.2 탭 제목 (1차)

| ID | 요구사항 |
|---|---|
| FR-10 | 탭 제목 형식: `<상태 아이콘> <별칭> [<계정>] · <세션 부제>`. 예: `✳ claude_env [개인] · 로그인 버그 수정`. 첫 프롬프트 전에는 `<상태 아이콘> <별칭> [<계정>]`이다. |
| FR-11 | 상태 아이콘(작업 중·대기·입력 필요)은 Claude Code가 지금 그리는 것을 그대로 쓴다. 도구는 텍스트만 정한다. |
| FR-12 | 별칭의 기본값은 프로젝트 폴더 이름이고, 사용자가 프로젝트별로 바꿀 수 있다. |
| FR-13 | 세션 부제의 기본값은 첫 프롬프트 요약이다. Claude가 만드는 자동 제목을 얻을 수 있다고 확인되면 그것을 쓴다. 사용자가 세션별로 바꿀 수 있다. 같은 프로젝트의 탭은 부제로 구분하고 `·2` 같은 번호는 붙이지 않는다. |
| FR-14 | 상태가 바뀌어도 아이콘만 바뀌고 별칭·계정·부제는 유지된다. |
| FR-15 | 사용자가 `--name`이나 `/rename`으로 직접 이름을 주면 그 이름을 그대로 두고, 그 탭의 제목은 도구가 관리하지 않는다. 설정 화면에서 다시 관리하게 할 수 있다. |

### 4.3 트레이 설정 UI (1차)

| ID | 요구사항 |
|---|---|
| FR-16 | 트레이 아이콘으로 상주하고 로그인 시 자동으로 시작한다. |
| FR-17 | 설정 창에서 다음을 편집하고, 재시작 후에도 유지된다: 복원 켜기/끄기, 프로젝트 별칭, 계정 표시 이름, 프로젝트별 실행 방식(A/C), 프로젝트별 C 작업 위치, 세션 부제, 자동 이어가기. |
| FR-18 | 복원을 끄면 도구가 바꿨던 Windows Terminal 설정도 원래 값으로 돌아간다. |
| FR-19 | 평소 사용에는 UI 조작이 필요 없다. 복원과 제목은 자동으로 처리된다. |
| FR-20 | 보기 좋고 세련된 설정 화면이어야 한다. |

### 4.4 계정 무중단 전환 (2차)

| ID | 요구사항 |
|---|---|
| FR-21 | 여러 구독 계정을 등록할 수 있다. |
| FR-22 | 현재 계정의 사용량(5시간 또는 주간)이 95%에 이르면, 응답 사이의 쉬는 틈에 다음 계정으로 바꾸고 같은 대화를 이어간다. 한도에 걸려 응답이 멈추기 전에 바꾼다. |
| FR-23 | 전환 후 탭 제목의 계정 표시가 바뀐다. |

## 5. 비기능 요구사항과 제약

| ID | 내용 |
|---|---|
| NFR-1 | Windows Terminal을 대체하지 않는다. 별도 트레이 앱과 CLI가 Windows Terminal 위에서 동작한다. |
| NFR-2 | 훅은 Claude 응답을 느리게 하지 않아야 한다. 도구 실행 파일의 훅 처리 목표는 p95 100ms 이하이고, 훅 안에서 네트워크나 느린 명령을 부르지 않는다. |
| NFR-3 | 설치·제거는 도구가 넣은 항목만 정확히 넣고 뺀다. Claude 설정, Windows Terminal 설정, 셸 프로필, 실행 정책의 원래 값을 기록했다가 제거할 때 되돌린다. 다른 도구(예: OMC)가 넣은 설정은 건드리지 않는다. |
| NFR-4 | 문서화되지 않은 내부 형식(Windows Terminal `state.json`)을 쓸 때는 형식을 먼저 검사하고, 모르는 형식이면 쓰지 않는다. |
| NFR-5 | Windows Terminal 밖(VS Code 터미널 등)에서 실행한 Claude 세션에는 영향을 주지 않는다. |
| NFR-6 | 트레이 앱이 꺼져 있어도 Claude와 터미널은 평소처럼 동작한다. 복원은 Windows Terminal 기본 동작(마지막 창만)으로 떨어진다. |

## 6. 제외 범위

- 자체 터미널 앱 개발
- API 키(Console) 계정
- VS Code 등 Windows Terminal 외의 터미널 앱
- WSL 안에서 실행한 Claude의 대화 복원(2차 이후 재검토)
- 1차에서의 계정 자동 전환
- 창을 닫은 뒤 백그라운드에서 계속 실행하는 방식을 **기본으로** 쓰는 것. 방식 C로 프로젝트별 선택만 허용한다.

## 7. 방식 C를 기본으로 바꾸는 조건

아래를 모두 만족하면 기본 실행 방식을 C로 바꾸고 A를 선택 사항으로 둔다.

1. 백그라운드 세션 확인 실험(S3)과 attach 상태 탭 제목 실험(S4(b)) 통과
2. C 프로젝트에서 14일 이상, 창 닫기 20회 이상 실제 사용
3. 그 기간에 응답 유실, 엉뚱한 세션 복원, 세션 분실이 0건
4. 사용자가 C의 사용감(전체 화면 표시, 터미널 스크롤백 없음)을 받아들임
5. 그 시점의 Claude Code 버전으로 S3를 다시 통과

## 9. 확인 실험이 필요한 가정

아래가 성립하지 않으면 해당 요구사항의 구현 방법이나 수준이 바뀐다. 실험 절차는 `docs/spikes/runbook.md`, `runbook-c.md`에 있다.

| 가정 | 관련 요구사항 | 실패하면 |
|---|---|---|
| Windows Terminal이 복원 뒤 각 셸의 폴더를 되살린다 (S1) | FR-3, FR-5 | 셸 통합을 고쳐 다시 시험 |
| 도구가 Windows Terminal 복원 파일을 고쳐 여러 창을 되살릴 수 있다 (S1) | FR-6 | `wt.exe` 명령으로 배치를 다시 여는 방식 |
| 훅 `sessionTitle`로 정한 이름이 아이콘과 함께 탭에 보인다 (S4) | FR-10, FR-11 | 훅이 직접 제목 문자열 출력. 그것도 안 되면 아이콘 포기(사용자 승인 필요) |
| Claude 자동 제목을 얻을 수 있다 (S4) | FR-13 | 첫 프롬프트 요약을 부제로 유지 |
| 창을 닫을 때 도구가 1초 안에 상태를 기록할 수 있다 (S2) | FR-1, FR-7 | 트레이가 프로세스 소멸로 판단 |
| 백그라운드 세션이 Windows에서 동작한다 (S3) | FR-1(C), FR-8, FR-9 | **방식 C 없이 A만 제공.** 응답을 끝까지 마치는 보장은 없음 |
| 알림 클릭으로 앱을 깨울 수 있다 (S3) | FR-8 | 트레이 메뉴로 열기 |
